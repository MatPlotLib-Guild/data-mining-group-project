Phase 01 · Business Understanding05 / 14
1.1 Objectives

Rank newly opened PRs by merge likelihood — before maintainers spend a minute on them.

The model is a prioritization layer on top of GitHub's firehose. It does not reproduce maintainer reasoning; it surfaces probable outcomes from public signals.

Decision-support value

For a team reviewing 500 PRs/month, even a 10% triage saving recovers ≈ $1,512 / yr at $30/hr.

1.3 Data-mining goals
  • G·01Convert raw GH Archive events into a PR-level supervised dataset.
  • G·02Predict P(merged = 1 | X) as binary classification.
  • G·03Compare linear and non-linear models under one shared split.
  • G·04Identify which pre-opening signals drive merge ranking.
  • G·05Keep all features compliant with PR-publication-time information.

3.1 — 3.5 Pipeline

Five steps. One leakage-aware table.

Step 01
Select
Retain PRs with both opened & closed events containing merge label.
Step 02
Clean
Sort by timestamp, keep first opening / first closing per PR id.
Step 03
Construct
Target merged ∈ {0,1}; merge rate 0.8574.
Step 04
Integrate
Join opening + closure + previous-day repo / actor history.
Step 05
Format
26 numeric features × 195,425 rows. Median-imputed.
Opening-time features

commits · additions · deletions · changed files · opening hour · weekday · weekend · draft · log-size variants.

Repository history

Previous-day repo events, PRs, issue-comments, push events, cumulative actor-days.

Actor history

Previous-day actor activity, PR volume, comment volume, push activity, repo-days.

Leakage rule

For a PR opened on date d, every event from date d is excluded from history features. Closure-time fields are never inputs.

6.1 Recommended use

A maintainer dashboard, not a merge gate.

  • SHOWPredicted merge probability + non-merge risk score.
  • SHOWMost important feature groups: repo activity, contributor history.
  • WARNData limitations and model scope, on-screen.
  • NEVERAuto-reject, hide, or deprioritize a contributor.
6.4 Lessons & next steps

What we proved — and what's next.

Proved

Public, pre-opening event signals carry useful ranking signal for PR merge outcomes. Repository & contributor context dominate raw PR size.

Open

Longer archive window · exact-timestamp history · early-interaction features (first 6–24h) · time-based validation · richer GitHub fields.

Final position

A proof-of-concept ranking model for PR outcome risk — useful for prioritization, insufficient for automation.
